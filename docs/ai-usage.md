# My Personal AI Usage Rules

## Rule 1 — What I will never paste

Before sharing code, routes, tests, frontend files, logs, or outputs with an AI tool, I will first check that the material contains no credentials, secrets, production URLs, authentication secrets, real user data, real records, proprietary logic, or private assets.

If any of these are present, I will remove or replace them with safe placeholders before sharing.

## Rule 2 — What I will always verify before accepting

I will not accept AI-generated backend code, frontend code, CI YAML, Dockerfile changes, security findings, or plans until I have reviewed them and performed the relevant verification available in the project.

I will run tests, CI checks, build or run commands, or compare the output against repository evidence when appropriate.

If an important part is unclear, I will review or trace it before relying on it.

## Rule 3 — How I will record AI contributions

For each significant AI-generated contribution I keep, I will record what the AI generated, what I reviewed, how I verified it, and any unclear parts that still need follow-up.

I will keep this evidence in the appropriate project documentation, prompt log, verification notes, or commit-related notes so that I can later explain what was generated, what I accepted, and why.

## When I will re-read this

I will re-read these rules 30 days from today and revise them if my AI-assisted development workflow or risk level changes.
