# Course Reflection

This course changed how I think about AI coding tools. I no longer see them as one interchangeable assistant. Different tool shapes are better for different kinds of work.

For reasoning, drafting, learning unfamiliar concepts, and reflecting on decisions, I prefer general chat. For repository-level planning, review, governance, and read-only analysis, I prefer Codex App because it can work with the project context directly. For larger implementation loops, I would use an agent-style coding tool such as Cursor, while terminal-heavy delivery and infrastructure work fit better with a terminal-focused agent. Continuous editor pairing can also be useful for smaller code changes where the scope is already clear.

The biggest lesson for me is that smooth AI output is not the same as verified output. Throughout the course, testing, reviewing files, checking failure logs, comparing context strategies, and inspecting generated infrastructure all showed me that AI works best when I give it evidence and then verify what it produces.

My single most important rule is:

**I do not accept AI output until I understand enough of it to verify and own the final result.**

AI can generate, explain, review, and suggest, but I am still responsible for the final artifact.
